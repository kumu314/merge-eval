# 判据自证性检查卡

沉淀自三次真实翻车：三次都是**判据自己证明自己成立**，三次都跑出了漂亮的"通过率",
三次都是靠"把目标从证据集里挖掉再算一遍"才暴露。

## 0. 一句话命题

> **当 X 满足条件 C 时，判定 X 属于类别 Y。**
> 先问：**C 用到的证据，会不会包含 X 自己？**
> 若包含，X 既是"待判的东西"又是"判定它成立的证据" —— 判据**自我满足**，
> 永远成立、永远不可证伪。你测到的是**同义反复**，不是事实。

**同一个坑还有第二个入口**：C 的证据不是 X 自己，而是**判据作者自己写死的硬编码串**
（如"命中『每天慢读三遍』说明这是模板"）。这也算自证 —— 它证明的是
**"生成器今天用了这个词"**，不是"这不是模板"。

## 1. 三个真案例（三种形态，对号入座）

### 形态 A：证据集里装着目标本身

西江阅 TTS #58v2：把「斜」的叶韵判据改成「斜处于分句末 **∧** 本诗押麻韵」，
其中"本诗押麻韵"由 `poemRhymesMa()` 扫描全诗末字实现，而它的证据串是

```js
MA_RHYME = "家花纱华沙茶麻瓜娃芽鸦葩笳奢衙槎夸斜"   // ← 末尾就写着「斜」
```

于是**只要某句末是"斜"，"本诗押麻韵"就被"斜"自己证实了**。
结果：`蓦山溪`（全篇仄韵，根本不押麻韵）、`新水令`（车遮韵 -ie）被误判为麻韵，斜被读错。

### 形态 B：判据写死了自己造的字符串（和生成器赛跑，且你已经输了）

西江阅 #62：代码里

```js
const memTpl = expand && (!mem.length || mem.some(m => /它是全篇的眼|每天慢读三遍/.test(m.d||"")));
```

按句式做**跨篇统计**后，发现存在两个只差一个字的变体：

| 层级 | 篇数 | 记忆卡末句 | 是否被检出 | 用户看到 |
|---|---|---|---|---|
| 拓展 | 710 | 每天**慢**读三遍 | ✅ 命中 | 诚实显示「记忆要点待补」 |
| 精读 | 40 | 每天**读**三遍（少一个"慢"字） | ❌ 逃逸 | **量产模板被当成真内容展示** |

生成器改一个字，检测器就瞎了。更糟的是这 40 首以"精读"身份绕过了 `expand &&` 限制，
于是出现了最坏组合：**710 首诚实标注"待补"，40 首反而伪装成完整**。

### 形态 C：断言抄了设计者的决定（同义反复测试）

形如「当设计者决定 X 时，`expect(X)`」——测试必然通过，但只证明了"代码遵循了作者意图"，
没证明"这个意图是对的"。**复跑别人的测试"全过"了，也要先看断言里写死了什么。**

## 2. 两条探针（都可复用）

### 探针 1：挖除探针 —— 把目标从证据集里挖掉再算一遍

```js
// 例：反循环探针——排除目标字后，判据是否仍成立？
function maEvidenceExceptXie(lines){
  return lines.some(l => String(l).split(SPLIT).some(t => {
    const last = t.trim().slice(-1);
    return last && last !== '斜' && MA_RHYME.includes(last);  // ← 排除「斜」自己
  }));
}
// 命中项中 maEvidenceExceptXie === false 的，就是"唯一证据 = 目标本身"的循环项
```

本次跑出 **12 处命中里恰好 2 处循环**，与人工核对韵脚（蓦山溪 / 新水令）**完全吻合** ——
**探针误报率 0，且直接给出修法**（把"斜"移出 `MA_RHYME`）：`保留 10 处正确、消除 2 处误伤`。

**判据：结论翻转 = 循环。**

### 探针 2：跨样本重复度探针 —— 不依赖任何具体措辞

适用于「这是不是模板 / 量产 / 特例」这类判定。**把专有名词抹平后统计跨样本出现次数**：

```js
const norm = s => String(s||'')
  .replace(/《[^》]+》/g, '《X》')   // 抹掉篇名（填空模板的填空位）
  .replace(/「[^」]+」/g, '「Y」')   // 抹掉引文
  .replace(/\d+/g, '#');            // 抹掉数字
const tpl = {};
for (const p of batch)
  for (const seg of String(p.d).split(/[。；;]/)) {
    const t = norm(seg).trim();
    if (t.length < 8) continue;                     // 太短不具判别力
    (tpl[t] = tpl[t] || { n: 0, ids: [] }).n++, tpl[t].ids.push(p.id);
  }
const repeated = Object.entries(tpl).filter(([, v]) => v.n >= 2);  // ≥2 个样本复用即判模板
```

**两个使用要点（缺一不可）**：

1. **必须同时准备阴性对照。** 拿它跑 batch-03（90 条记忆卡）得 **0 种重复** → 真逐篇写的；
   跑那 40 首得 **40 篇同一句式**。**判据若不能把这两组分开，说明阈值/归约还没调对。**
2. **别把检测限定在某个层级或开关里**（原代码的 `expand &&`）——模板与层级无关，限定就给逃逸留了门。

## 3. 四步检查流程

1. **找出 C 的全部证据来源** —— 别只看主逻辑，**要看它调用的常量、白名单、辅助函数**
   （形态 A 的根因藏在 `MA_RHYME` 这个常量里，主逻辑看着完全无辜）。
2. **两问**：证据集里有没有 X 自己？有没有我自己写死的串？
3. **跑探针**：形态 A → 挖除探针；形态 B → 跨样本重复度探针；形态 C → 看断言是不是抄了决定。
4. **给阴性对照**，确证判据能把"真阳性"和"自证阳性"分开。

## 4. 三类修法

| 修法 | 适用 | 例 |
|---|---|---|
| 把目标移出证据集 | 形态 A | 把「斜」移出 `MA_RHYME` |
| 要求 ≥1 个**非目标**的独立证据 | 形态 A | "本诗押麻韵"须有 ≥1 个非"斜"的麻韵字 |
| 换成不依赖措辞的统计量 | 形态 B | 跨样本重复度替代固定字符串匹配 |

## 5. 失败模式（都是踩过的）

- **只看"误伤降了没有"就判修复成功。** 循环误伤往往**恰好落在"看起来最像正例"的那几条上**
  （句末、形态完美、长度达标），人眼最难发现。修完必须专门跑一遍**反循环探针**。
- **用硬编码串做检测 = 和生成器赛跑。** 生成器改一个字就失效，而且不会报错 —— 你只会看到"命中数变少了"，
  误以为是内容变好了。
- **把检测限定在某个层级/开关里**（`expand &&`），给逃逸留门。
- **"零命中"不等于"判据对了"。** 可能是探针本身没跑到（如驱动用错入口函数，测的是未渲染骨架）。
  零命中先怀疑工具，再怀疑对象。

## 6. 与相邻技能的分工（避免重复承担）

| 技能 | 讲什么 | 与本颗的界线 |
|---|---|---|
| `evidence-discipline` | **写作**领域：抽象判断要退回可观察证据（"这段有点空/像AI写的"） | 面向文案可信度；本颗面向**技术判据/分类器**的逻辑结构。触发词不重合 |
| `blackboard-write-integrity-check` | 黑板写入的**落盘取证**（sha256 是否真写进列） | "写完怎么自证真的落盘"；本颗是"判据本身是否自证" |
| `local-html-verify` | 本地 HTML 应用的独立复核 | 场景限定在 HTML 验证；本颗是**通用的判据结构检查**，任何规则/分类器评审都适用。该颗原含「启发式判据自证」「跨篇重复度」两节，**已收窄为指向本颗的指针**（同一内容放两处会重复承担、摊薄路由准确率） |
| `agent-runtime-boundaries` | 替换操作的**计数自证**（MISS/DUP 闸） | "操作有没有生效"的自证；本颗是"判定逻辑有没有自我满足" |

> 若你是在**验证一个 HTML 应用**时撞到判据问题，两颗都可能命中 —— 先看本颗（判据结构对不对），
> 再看 `local-html-verify`（怎么在真渲染里取证）。
